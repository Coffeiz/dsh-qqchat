# PRD 撰写规范

本目录存放 dsh-qqchat 的产品需求文档。PRD 用于描述产品目标、功能契约、技术
边界、验收方式和唯一实施清单；实现状态以文档头部和“实际状态”为准。

## 文件命名

使用：

```text
PRD-<领域>-<编号>-<中文主题>.md
```

例如：`PRD-MEM-1-群记忆与群友记忆策略调整.md`。

- `MEM` 表示记忆领域；其他领域可以使用 `IM`、`UI`、`SEC` 等短标识。
- 编号按领域递增，不使用全局流水号。
- 主题使用简短中文，不堆叠英文缩写。
- 同一领域的延续性工作优先更新原 PRD；全新独立特性再新建文档。

## 文档头部

```markdown
# PRD 标题

> 状态：当前实际能力和缺口
> 创建：YYYY-MM-DD
> 最近更新：YYYY-MM-DD
> 关联模块：`path/to/file.ts`、`path/to/other.ts`
> 背景参考：参考实现、调查报告或相关文档
```

“状态”描述真实结果，不写 Phase 作为状态。代码、测试或验证结果发生变化时，
必须同步更新状态和最近更新日期。

## 推荐章节顺序

1. **实际状态**：只读摘要表，说明当前能力和结果，不列任务。
2. **背景与目标**：现状、问题、目标和非目标。
3. **功能需求**：使用 `FR-<领域>-<编号>` 编号，描述目标行为和边界。
4. **技术方案**：职责、数据、依赖、兼容性、隐私和错误处理。
5. **验证与上线**：验收方法、测试命令、观测、灰度和回滚。
6. **风险与待确认问题**：先列风险，再列尚未定案的问题。
7. **唯一实施 TODO**：全文唯一的可执行复选清单。

只有“唯一实施 TODO”可以使用 `[ ]` 和 `[x]`。其他章节不得用复选框表达进度，
也不得创建“剩余工作”“Phase TODO”或“验收清单”等第二个任务来源。

## 状态标记

- ✅ 已完成：代码已合并并验证。
- 🟡 部分完成：已有可运行实现，但仍存在明确缺口。
- 🔲 待评估：尚未实现或尚未完成真实环境验证。
- 🚧 进行中：正在实施。

TODO 按 Phase 分组时，每条任务必须有稳定编号、独立复选状态、责任边界和验收
标准。需求、方案和验收章节只引用任务编号，不复制任务内容。

## 语言与链接

正文使用简体中文；代码标识、字段名、环境变量和命令用反引号包裹。文档之间使用
相对路径，必要时同时链接 `docs/README.md` 中的导航入口。
